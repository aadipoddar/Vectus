1Overview & how it fits

Payroll is a new domain area that mirrors the existing Accounts/Fleet pattern exactly: feature folders of {Models, Data, Exports}, Insert_* upsert procs, a Status soft-delete bit on every table, and an audit row on every mutation.

Setup masters→ Assign salary structure→ Enter attendance→ Process run (engine)→ Review payslips→ Finalize → post journal
The one big idea: every pay head (Basic, HRA, PF, ESI, PT…) and every statutory rate is a data row, not code. Adding a new allowance or changing the PF rate next budget is an INSERT — the calculation engine never changes. That is what makes the module reusable in any project.

5Statutory configuration (the rules)

Header/detail: a StatutoryRule is the stable identity; its rates, ceilings and caps live in effective-dated StatutoryRate lines (PT/TDS bands in StatutorySlab, owned by the rate). A budget change = a new dated line, never an edit — so old runs still recompute on the old line.

Header/detail split: Code · Name · A/c · Ledger · StateUT sit on the StatutoryRule header (edited in place); Rate · ceiling · cap · the TDS knobs · EffectiveFrom sit on the StatutoryRate line. Changing a rate adds a new dated line — the old line stays, so past runs recompute unchanged.

Two rules the engine enforces beyond the rates: (1) 50% wage floor — under the 2025 Labour Codes, PF wage = MAX(Basic+DA, 50% of gross), so a low basic can't shrink PF. (2) ESI contribution period — once covered at a period start (Apr–Sep / Oct–Mar), ESI continues to period end even after gross crosses ₹21,000. For exempted establishments A/c 2 → 0.18% and A/c 22 → 0.005% (inspection charges).

6.5 Staff advances / loans

An advance is not a salary-structure line — it's a separate loan with a principal, a recovery schedule, and an outstanding balance that shrinks each month and stops when cleared. The payroll engine pulls the due installment automatically; it never over-recovers past the outstanding balance.

8The calculation engine, step by step

PayrollCalculationEngine.Compute(...) is a pure, database-free static class — fully portable and unit-testable. Order matters:

#StepWhat it does
1Proration factorPresentDays ÷ PayableDays (here 30/30 = 1.0).
2Resolve earningsFixed straight; PercentOfBase after its base is known (Basic → HRA/DA). Multiply each by the proration factor.
3GrossSum of earnings.
4PFPF wage = MAX(Σ AffectsPFBase, 50% of gross), capped ₹15,000. Then split: EE 12% · EPS 8.33% (cap ₹1,250) · EPF = 12%−EPS · EDLI 0.5% · admin 0.5% (min ₹500).
5ESIIf gross ≤ ₹21,000 or still within the active contribution period: × 0.75% / 3.25%. Else zero.
6PTSlab lookup on gross for the employee's state.
7TDSTaxable earnings annualized → regime slab → ÷12. (Can start as a manual override field.)
8Advance recoveryFor each active EmployeeAdvance with outstanding > 0, take the due installment capped at the outstanding balance; write an AdvanceRecovery row and reduce OutstandingBalance (auto-closes the loan at zero).
9NetGross − (employee deductions + PF emp + ESI emp + PT + TDS + advance installments).
10Emit detailsOne PayrollLineDetail per component for full transparency.
For each StatutoryRule the engine takes the StatutoryRate line (and its slabs) with the latest EffectiveFrom ≤ run period — so a rate change is a new dated line and historical/arrear runs stay correct.

11Compliance & team-discussion notes

  • EPF — modelled as six sub-rules across EPFO accounts A/c 1/2/10/21/22: EE 12%, EPS 8.33% (cap ₹1,250), EPF (12%−EPS), EDLI 0.5%, admin 0.5% (min ₹500), inspection (A/c 22, NIL un-exempted / 0.005% exempted). Full breakdown in PayrollModule.PFEcr.html.
  • ESI — 0.75% employee / 3.25% employer; covered while gross ≤ ₹21,000, and the contribution-period rule (Apr–Sep / Oct–Mar) keeps coverage to period-end after a mid-period crossing. Both in the engine (§8 step 5).
  • Professional Tax — West Bengal slabs (Durgapur). Stored as StatutorySlab rows so other states are just more rows.
  • TDS — new regime default under the Income-tax Act 2025 (FY 2026-27): std deduction ₹75,000, §87A rebate ₹60,000 (nil to ₹12L), 4% cess — all columns on the TDS StatutoryRate line, never engine literals, so a Budget change is a new dated line. Manual override to start, annualized projection in Phase 3.
  • Labour Codes 2025 — the 50% wage-floor rule is enforced (PF wage = MAX(Basic+DA, 50% of gross)); the per-component AffectsPFBase/AffectsESIBase flags keep any further definition change a config edit.
  • Arrears — retrospective revisions are computed per origin month with PF/ESI on arrears and §89(1)/Form 10E tagging — see PayrollModule.Arrears.html.
  • Still open for the team: overtime formula · gratuity & leave encashment in full-and-final · bonus (Payment of Bonus Act) · LWF figures · multi-company posting ledgers.

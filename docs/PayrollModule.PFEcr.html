1What the ECR is

The Electronic Challan-cum-Return is the single monthly PF filing. One text file, uploaded to the EPFO Unified Employer Portal, that both returns each member's wages/contributions and generates the challan to pay.

Finalize payroll run→ Generate ECR .txt→ Upload to Unified Portal→ Portal returns TRRN + challan→ Pay online by 15th
FrequencyMonthly — due by the 15th of the following month.
File typePlain text, extension .txt, UTF-8.
Delimiter#~# (hash-tilde-hash) between fields.
RowsOne line per member (employee). No header or trailer line in ECR 2.0.
ColumnsExactly 11, in the fixed order shown below.
AmountsWhole rupees only — no decimals, no commas, no currency symbol.

2The 11-column format

Each line is these 11 fields joined by #~#. The right column shows where the value comes from in our PayrollLine.

#FieldMeaningSource in Vectus
1UAN key12-digit Universal Account NumberEmployee.PFUAN
2Member NameName as per EPFO recordsEmployee.Name
3Gross WagesTotal monthly gross paidPayrollLine.GrossEarnings
4EPF WagesWage on which PF is figured (capped ₹15,000 unless higher-wage opt-in)PayrollLine.PFWage
5EPS WagesPension wage = min(PF wage, ₹15,000); 0 if not an EPS memberderived from PF wage
6EDLI WagesInsurance wage = min(PF wage, ₹15,000)derived from PF wage
7EPF Contri (EE)Employee share = 12% × EPF wagesPayrollLine.PFEmployee
8EPS Contri8.33% × EPS wages (cap ₹1,250)PayrollLine.PFEmployerEPS
9EPF-EPS Diff (ER)Employer EPF share = (12% × EPF wages) − EPSPayrollLine.PFEmployerEPF
10NCP DaysNon-Contributory Period — unpaid/LOP days (0 if full month)AttendanceInput.LOPDays
11Refund of AdvancesPF advance refund, if any (usually 0)0 (Phase 3+)
Columns 8 & 9 are exactly the EPS/EPF split from the plan: the employer's 12% is divided into EPS (capped at ₹1,250) and the EPF remainder — so a wage above ₹15,000 correctly routes the excess into EPF.

7How the module generates it

PFEcrExport (under Payroll/Processing/Exports) reads the finalized run and writes the text file — no recomputation, just formatting.

  1. Load the run's PayrollLine rows joined to Employee (for UAN + name).
  2. Filter to members where IsPFApplicable and a valid PFUAN exists.
  3. For each, emit the 11 fields from the line's stored PF columns (already split & rounded at processing time — the export never re-derives money).
  4. Join fields with #~#, lines with newline, write .txt via the existing save/view service.
  5. Admin/EDLI/inspection totals are shown on a companion summary sheet for the user to cross-check the portal's challan.
Because amounts are snapshotted on PayrollLine at Finalize, re-exporting an old month always reproduces the exact file that was filed — even if rates changed since.

8Edge cases & validation

  • NCP days (col 10) — unpaid/LOP days in the month. Full month = 0; the engine fills it from AttendanceInput.LOPDays. EPFO uses this to validate wage proration.
  • Higher-wage members — if ContributeOnHigherPFWage, EPF wages (col 4) is the full Basic+DA, but EPS/EDLI wages (cols 5–6) stay capped at ₹15,000.
  • Not an EPS member — new joiners after 01-Sep-2014 earning > ₹15,000 have EPS wages = 0, EPS contri = 0; the whole employer 12% goes to EPF (col 9).
  • Exempted establishment — A/c 2 becomes inspection 0.18%, A/c 22 becomes 0.005% (min ₹1); selected by the company exemption flag.
  • Zero-wage month (full LOP / on leave) — member still listed with 0 wages and NCP = days, so EPFO keeps the account active.
  • Validation before export — UAN present & 12 digits; name not blank; col 7 = 12% × col 4 (within rounding); col 8 ≤ 1,250; col 9 = ER 12% − col 8; amounts are whole rupees.
The 11-column ECR 2.0 layout is current as of mid-2026. Confirm against the EPFO file-structure PDF on the Unified Portal before first filing, in case EPFO revises the format.
